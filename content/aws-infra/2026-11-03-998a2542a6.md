# Amazon Aurora MySQL 8.4.10 is now generally available

<p>Starting today, <a href="https://aws.amazon.com/rds/aurora/" rel="noopener noreferrer" target="_blank">Amazon Aurora MySQL-Compatible Edition</a> 8.4 supports MySQL 8.4.10. We recommend upgrading to the newer minor versions to accept fixes for Common Vulnerabilities and Exposures (CVEs) in prior versions of MySQL and to benefit from bug fixes, performance improvements, and new functionality added by the MySQL community. For more details, refer to the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraMySQLReleaseNotes/AuroraMySQL.Updates.84Updates.html" rel="noopener noreferrer" target="_blank">Aurora MySQL 8.4</a> and <a href="https://dev.mysql.com/doc/relnotes/mysql/8.4/en/news-8-4-10.html" rel="noopener noreferrer" target="_blank">MySQL 8.4.10</a> release notes.</p> 
<p>Aurora MySQL 8.4.10 adds support for global transaction identifiers (GTID) tags, which lets you assign a user-defined tag to GTIDs to help you identify and group related transactions in binary log replication. This release also adds support for a maximum of 50,000 simultaneous connections per DB instance, which allows connection-intensive applications to scale without adding a connection pooling layer. Learn more about maximum connections best practices in the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraMySQL.Managing.Performance.html#AuroraMySQL.Managing.MaxConnections" rel="noopener noreferrer" target="_blank">Amazon Aurora MySQL User Guide</a>.  </p> 
<p>You can upgrade your databases during scheduled maintenance windows using automatic minor version upgrades. To simplify operations at scale, enable <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraMySQL.Updates.AMVU.html" rel="noopener noreferrer" target="_blank">automatic minor version upgrades</a> and use the AWS Organizations <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Maintenance.AMVU.UpgradeRollout.html" rel="noopener noreferrer" target="_blank">Upgrade Rollout Policy</a> to orchestrate upgrades across your clusters in phases, validating on lower-priority environments before upgrading your most critical ones. You can perform minor version upgrades in-place or via snapshot restore. Learn more about performing version upgrades in the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/AuroraMySQL.Updates.Upgrading.html" target="_blank">Amazon Aurora User Guide</a>. This release is supported in all <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Concepts.RegionsAndAvailabilityZones.html#Aurora.Overview.Availability.MySQL" rel="noopener noreferrer" target="_blank">AWS Regions</a> where Aurora MySQL is available.</p> 
<p><a href="https://aws.amazon.com/rds/aurora/" rel="noopener noreferrer" target="_blank">Amazon Aurora</a> is designed for high performance and availability at global scale with full MySQL compatibility. It provides scale-to-zero serverless compute, Aurora Global Database for multi-Region resilience, Aurora I/O-Optimized for improved price performance on I/O-intensive workloads, and built-in security and continuous backups. To get started, take a look at Aurora's <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/CHAP_AuroraOverview.html" rel="noopener noreferrer" target="_blank">getting started page</a>.</p>
