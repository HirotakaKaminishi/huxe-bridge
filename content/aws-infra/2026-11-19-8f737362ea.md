# Amazon SageMaker AI now supports cross-Region inference routing

<p>Today, Amazon SageMaker AI announces cross-Region inference routing, which helps keep inference applications available when a region runs short of capacity by sending requests to endpoints deployed in other AWS Regions and AWS accounts. Models served on accelerated instances can reach capacity limits in a single Region, and an unhealthy endpoint can lead to throttling and errors for end users. Previously, teams had to build and maintain their own routing, health checks, and retry logic across Regions.<br /> <br /> With cross-Region inference routing in SageMaker AI, developers create an inference router, register the real-time endpoints, asynchronous endpoints, and inference components they already run, and point their applications at the router. The router prefers endpoints in its own Region, shifts new requests to healthy destinations in other Regions as errors rise, and returns traffic gradually after the local endpoint recovers. Existing endpoints, models, and containers do not change. Endpoint owners stay in control: an endpoint policy determines which routers in other accounts can use an endpoint, and an optional cross-Region traffic cap reserves capacity for the endpoint’s local callers. Each real-time response identifies the endpoint that served the request and the reason, and router metrics in Amazon CloudWatch show where traffic went.<br /> <br /> Cross-Region inference routing is available for real-time inference in 32 commercial AWS Regions, and for asynchronous inference in 25 Regions. There is no additional charge for cross-Region inference routing. Customers pay standard SageMaker AI pricing for the endpoints that serve requests and standard Amazon CloudWatch rates for router metrics. To learn more, see the <a href="https://docs.aws.amazon.com/sagemaker/latest/dg/inference-router.html">Amazon SageMaker AI Developer Guide</a> and <a href="https://aws.amazon.com/sagemaker/ai/deploy/">SageMaker AI Deployment page</a>.</p>
