# Amazon RDS for Db2 now supports self-managed Active Directory

<p><a href="https://aws.amazon.com/rds/db2/" target="_blank">Amazon Relational Database Service (Amazon RDS) for Db2</a> now allows customers to directly join their RDS for Db2 DB instances to the domains of self-managed Microsoft Active Directory (AD). Self-managed AD can be on-premises, on AWS, or in another cloud. Customers use Kerberos as the authentication protocol to enable single sign-on for their database users.<br /> <br /> Previously, to use Kerberos authentication against a self-managed AD with their RDS for Db2 instances, customers were required to deploy AWS Managed Microsoft AD and establish a trust between the AWS managed domain and the self-managed domain. Now, customers can use their existing self-managed AD directly to authenticate and authorize database users without the additional complexity of a managed directory or a directory trust — helping them meet compliance requirements with their existing identity infrastructure. Customers can domain-join their RDS for Db2 instance by either creating a new instance or modifying an existing one, supplying the credentials of a delegated AD service account stored in AWS Secrets Manager and encrypted with AWS KMS. Customers can use self-managed AD free of charge.<br /> <br /> Self-managed Active Directory with Amazon RDS for Db2 is now generally available in all AWS Regions where Amazon RDS for Db2 is available, including the AWS GovCloud (US) Regions.<br /> <br /> To learn more and get started with self-managed Active Directory, visit the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/db2-self-managed-active-directory.html" target="_blank">Amazon RDS for Db2 User Guide</a> and the <a href="https://aws.amazon.com/rds/db2/" target="_blank">Amazon RDS for Db2 product page</a>.</p>
