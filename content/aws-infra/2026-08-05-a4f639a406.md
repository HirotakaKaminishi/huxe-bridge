# [Preview Announcement] Re-introducing Forward Proxy as AWS Network Firewall Functionality

<p>You can now use your Network Firewall with all its existing filtering capabilities and features as an explicit forward proxy.<br /> <br /> On Nov 25, 2025, AWS introduced Network Firewall <i>proxy </i>in public preview to help customers exert centralized security controls against data exfiltration and malware injection. At the time, the Network Firewall <i>proxy</i> was introduced as a standalone product, separate from Network Firewall <i>transparent firewall </i>and used its own separate <i>proxy </i>security policy. Customers who tested it in preview shared that they want the Network Firewall <i>proxy </i>to maintain parity with Network Firewall’s existing set of capabilities and use the same security policy across the two functionalities<i>.</i> In keeping with customer feedback, we are reintroducing explicit <i>proxy</i> as a functionality of Network Firewall. With this launch, you can configure Network Firewall with your existing Firewall policy in a new <i>no-source-preservation</i> deployment where it can be used as an explicit <i>proxy</i> with all its existing features including managed rule groups, active threat defense, Geo-IP filtering, URL and domain category filtering, container attribute-based rules for Amazon EKS and Amazon ECS, etc. You can create a single security policy and use it for both explicit <i>proxy</i> and <i>transparent firewall</i> functionalities.<br /> <br /> Try out AWS Network Firewall in <i>no-source-preservation</i> deployment with <i>proxy</i> functionality in your test environment today in US East (Ohio) region. <i>no-source-preservation</i> Network Firewall is available for free during public preview. For more information, check <u><a href="https://docs.aws.amazon.com/network-firewall/latest/developerguide/nfw-no-source-preservation.html">no-source-preservation Network Firewall documentation</a></u>.</p>
